# 磁带灾备恢复演练（Flask）

灾备值班员只有一台带机、两盘磁带，需要从带卷还原虚拟机镜像。本项目用本地文件
模拟磁带卷，提供一个 Flask 网页来选择带卷、填写**读带块数上限**与**暂存块数
上限**，并在额度内完成恢复演练；遇坏块或额度不足时报错，且保留上一次成品。

## 核心规则：开带前只凭清单判定额度

恢复分两个阶段：

1. **清单预演（不读带）**：规划器只用 `manifest.json` 里每块的磁带号、帧位置
   推演所有可行的顺读方案。顺读提前遇到的未来块有两种处置——**暂存**（占暂存
   额度）或**丢弃后回卷/换带重读**（占读带额度，重读帧重复计数）。规划器在
   给定双额度内求最优方案；**无解时一次带都不读**，页面归类为
   “额度不足（预演）”。
2. **按方案实读**：逐帧读带，跳过与重读都计读带量；每帧**读到时**核对
   SHA-256，暂存块**写出前**再核对一次；实读才可能发现坏块，页面单独归类为
   “坏块（实读）”。

## 磁带与恢复语义（按演练规则实现）

- 每套带卷最多两盘磁带、合计最多 12 个 **4 KiB** 镜像块；`manifest.json`
  记录每块的镜像块号、所在磁带、带上帧位置与 SHA-256，每块只出现一次。
- 磁带只能**从头顺读**。换带或回卷后，磁头回到第 0 帧；同一盘带在一次顺读
  会话内磁头自然前移，目标帧落后于磁头时才回卷。
- 顺读路径上**跳过的帧也算读带量**，回卷/换带后**重读的帧重复计数**。
- 提前读到、暂时不能按块号写出的块进入**暂存区**（内存/磁盘等价：Web 实跑用
  落盘临时文件，测试可走内存，两者统一按块数计入暂存额度），暂存块数峰值受
  暂存额度约束；暂存不下的块可以丢弃，待其成为目标块后回卷/换带重读。
- 镜像只允许按块号 0、1、2…… **顺序追加**，不能回读、不能改已写块。
- 每个块在**读到时（入暂存/直接写出前）**与**由暂存写出前**都核对 SHA-256；
  坏块立即失败。
- 任一额度不足在**开带前的清单预演**阶段即判定（实读量为 0），实读阶段只可能
  因坏块失败；失败删除半成品 `image.bin.part` 与暂存文件，**上一次成品
  `image.bin` 原样保留**；恢复期间仍可下载上次成品（原子发布）。

## 目录结构

```
app/
  storage.py   带卷发现、manifest 校验、定长帧顺读
  planner.py   清单驱动的恢复规划器：记忆化 DFS + 帕累托前沿，只凭清单判定
               双额度可行性，输出可执行的顺读/回卷/换带方案（不读带）
  engine.py    恢复引擎：执行规划方案、磁头/换带/回卷、读带与暂存额度、
               两次摘要核对、内存/磁盘等价暂存、只追加写
  web.py       Flask 应用、后台恢复线程、任务状态、成品下载
  templates/   单页界面（选带卷、填额度、轮询状态与用量、下载成品）
scripts/
  make_samples.py  生成三套样例带卷
tests/         引擎与 Web 自测（32 个用例）
run.py         本地开发入口
Dockerfile, docker-compose.yml
```

## 三套样例带卷（`scripts/make_samples.py` 生成）

| 带卷 | 布局 | 读带量 | 暂存峰值 | 换带 | 回卷 |
|---|---|---|---|---|---|
| `sample-ordered` | 块号沿顺读方向递增，块 0 在带头 | 12 | 0 | 1 | 0 |
| `sample-scrambled` | 每盘带块号沿顺读方向递减，未来块必须暂存 | 12 | 10 | 1 | 0 |
| `sample-bad` | 同乱序布局，块 11 带数据被故意损坏 | 失败 | — | — | — |

> 页面上每套带卷显示的“参考估算 读带/暂存”是**单一贪心读法**（提前读到的块
> 全部暂存）的指标，仅作参考，不是可行性判据。真实可行性由开带前的清单预演
> 按所填额度枚举“暂存/丢弃 + 回卷重读”策略后判定；页面同时展示本次任务的
> 实读块数与暂存峰值（运行中实时刷新、结束后定格）。
>
> 例：一盘带按 1、2、0 顺序存放镜像块时，填读带 4 / 暂存 1：预演给出
> “暂存块 2、丢弃块 1 → 写出块 0 → 回卷重读块 1”的方案，实读恰好 4 块、
> 暂存峰值 1，完整交付 3 块镜像。

## 本地运行

```bash
# 1) 安装依赖（无 pip/venv 的隔离环境可装到独立目录并用 PYTHONPATH 引用）
pip install -r requirements.txt

# 2) 生成样例带卷
python -I scripts/make_samples.py --root data/tapes

# 3) 启动（默认 0.0.0.0:8000）
python -I run.py
# 或 gunicorn（与容器一致，单 worker 多线程以保证任务状态语义）
python -m gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 run:app
```

环境变量：`TAPE_ROOT`（带卷根目录，默认 `data/tapes`）、
`OUTPUT_ROOT`（成品目录，默认 `data/output`）、
`READ_DELAY`（每读一块的模拟延迟秒数，默认 `0.05`，设 0 最快）。

## Docker Compose

```bash
docker compose up --build
# 打开 http://localhost:8000
```

镜像内置三套样例带卷；带卷与成品分别挂载在命名卷 `tape-data`、`output-data`
（`/data/tapes`、`/data/output`）。

## 自测

```bash
python -I -m unittest discover -s tests -v
```

覆盖（32 个用例）：顺序/乱序恢复、1·2·0 题面回归（读 4/暂存 1 卡线成功与
各档无解）、清单预演零读带、额度不足与实读坏块的分类区分、读带与暂存额度
卡线、紧暂存靠回卷/换带重读换空间、跳过帧与重读计数、回卷策略、内存/磁盘
暂存等价与清理、坏块检测与块号上报、清单非法（重复块、超 12 块、带文件
截断、路径穿越）、Web 成功交付与逐块摘要核对、失败保留上次成品、恢复中
下载、运行中实时指标、并发拒绝、非法入参。

## 实现、验证与未完成项

### 已实现
- **清单驱动规划器（`app/planner.py`）**：记忆化 DFS 枚举每个顺读 pass 内
  未来块“暂存/丢弃”的选择，按（读带量, 暂存峰值）保留帕累托前沿；开带前
  只凭清单求双额度内的最优方案（先省读带再省暂存），无解直接判定且不读带，
  错误信息附带最少读带量等放宽建议。
- 带卷清单严格校验：块号连续、每块唯一、帧位置连续、带文件大小精确匹配、
  最多 12 块/两盘带、目录名防穿越。
- 完整磁带机械语义：挂带、换带、磁头前移、回卷，跳过与重读均计读带量；
  引擎只负责执行规划方案，实读指标与规划指标逐项一致。
- **内存/磁盘等价暂存区**：Web 实跑提前块落盘（`<output>/<set>/staging/`），
  测试可走内存；两种承载统一计入暂存块数，结束自动清理无残留。
- 只追加镜像输出（内存 sink 供测试，文件 sink 经 `.part` + `os.replace`
  原子发布）；读到时与写出前两次 SHA-256 核对。
- 失败分类：`quota`（清单预演，实读量为 0）与 `bad_block`（实读发现，带
  坏块号）在 `/status` 与页面上明确区分；失败即停、保留上次成品；恢复中
  可下载；页面展示运行中实时实读量/暂存峰值，结束后定格本次实读指标，
  贪心估算标注“参考”。
- Dockerfile + docker-compose，镜像内置样例。

### 已验证
- 31 个单元/集成测试全部通过（`python -I -m unittest discover -s tests`）。
- 随机布局差分自测：300 套随机带卷 × 全额度网格，规划器与引擎实读的
  读带量/暂存峰值/回卷/换带逐项一致；无解方案实读量恒为 0；随机损坏块
  一律被实读阶段的 SHA-256 核对捕获。
- 端到端脚本验证：成功交付镜像并逐块核对 SHA-256；预演额度不足（零读带）
  与实读坏块分类正确且成品保留；恢复中下载与并发拒绝生效。
- gunicorn 单 worker 多线程实际启动，`/`、`/status`、`/download` 均 200。

### 未完成 / 限制
- 本环境无 docker 二进制，compose 配置仅做静态校验，未实际 `docker build`
  （Dockerfile/compose 沿用已验证可工作的结构，仅应用代码更新）。
- 恢复任务状态保存在单进程内存中（因此 gunicorn 固定单 worker）；多副本
  部署或进程重启后任务历史不保留（成品文件仍在）。
- 规划器按演练上限（最多 12 块、两盘带）设计，DFS 状态空间在该规模下
  毫秒级；若放宽块数上限，需要改成更紧的搜索剪枝或整数规划建模。
- 磁盘暂存按“与内存等价”的口径只模拟块数额度，未单独模拟暂存 IO 带宽/
  吞吐限制。
